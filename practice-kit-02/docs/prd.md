# PRD — 점심 메뉴 주문 취합 (모의 개발용)

## 1. 목적
팀원이 점심 주문 모집을 열고, 각자 메뉴를 주문하고, 개설자가 마감해 메뉴별 수량·금액을 한눈에 취합하는 웹 서비스.
해커톤 전 **BDD → AI 구현 → E2E 검증** 사이클을 연습하기 위한 축소 범위 프로젝트 (kit-02).

## 4. 용어
- **모집(Round)**: 특정 날짜의 점심 주문 묶음. 개설자, 날짜, 제목, 상태(`모집 중` / `마감`)를 가진다.
- **주문(Order)**: 모집 안에서 한 사용자가 고른 메뉴와 수량. **한 모집에 1인 1주문.**
- **취합표**: 모집의 주문을 메뉴별로 합친 수량·금액과 총액.

## 5. 요구사항

### REQ-01 모집 개설 및 주문 (P0)
- 로그인한 사용자는 날짜와 제목을 입력해 모집을 연다. 개설자는 모집을 연 사용자다.
- 모집 중인 모집에 메뉴와 수량(1~5개)을 골라 주문한다. 요청사항(선택, 50자 이하)을 남길 수 있다.
- 주문은 DB에 저장되며, 새로고침 후에도 모집의 "주문 현황"에 표시된다.
- 한 모집에 같은 사용자는 한 번만 주문할 수 있다. 바꾸려면 취소 후 다시 주문한다.

**인수조건**
- AC-01: 날짜와 제목을 입력해 모집을 열면 "모집" 목록에 표시된다.
- AC-02: 메뉴와 수량을 골라 주문하면 "주문 현황"에 주문자 이름·메뉴·수량이 표시되고, 새로고침 후에도 유지된다.
- AC-03: 수량이 1 미만이거나 5 초과이면 "수량은 1개 이상 5개 이하로 입력하세요" 오류가 표시되고 주문은 생성되지 않는다.
- AC-04: 같은 모집에 이미 주문했으면 "이미 주문했습니다" 오류가 표시되고 기존 주문이 유지된다.

### REQ-02 마감 및 취합 (P0)
- 개설자는 모집을 마감할 수 있다. 마감된 모집에는 주문을 추가할 수 없다.
- 모집 화면에 메뉴별 수량·금액과 총액을 취합표로 보여 준다. **금액은 서버가 DB의 메뉴 가격으로 계산**한다.
- 개설자가 아닌 사용자는 마감할 수 없다 (버튼 미노출 + API 403).

**인수조건**
- AC-05: 개설자가 모집을 마감하면 상태가 "마감"으로 표시되고 주문 양식이 사라진다.
- AC-06: 마감된 모집에 API로 직접 주문하면 **409** `ROUND_CLOSED`로 거부된다.
- AC-07: 취합표에 메뉴별 수량·금액과 총액이 표시된다. (주문이 없는 메뉴는 표시하지 않는다)
- AC-08: 개설자가 아닌 사용자에게는 마감 버튼이 없고, API로 직접 마감을 요청하면 **403**이다.

### REQ-03 주문 취소 (P0, 보안)
- 사용자는 모집 중인 모집에서 **본인 주문만** 취소할 수 있다.
- 다른 사용자의 주문에는 취소 버튼이 보이지 않는다.
- API로 다른 사용자의 주문 취소를 요청하면 **403**, 마감된 모집의 주문 취소는 **409**를 반환하고 주문은 유지된다.
- 로그인하지 않은 요청은 **401**을 반환한다.

**인수조건**
- AC-09: 본인 주문을 취소하면 "주문 현황"에서 사라지고 새로고침 후에도 없다.
- AC-10: 다른 사용자의 주문에는 취소 버튼이 없다.
- AC-11: 다른 사용자의 주문 취소 API 요청은 403, 주문은 유지된다.
- AC-12: 마감된 모집의 본인 주문 취소 API 요청은 409, 주문은 유지된다.
- AC-13: 비로그인 상태의 주문 생성 API 요청은 401.

### P1 (시간이 남으면)
- 주문 수정 (메뉴·수량 변경)
- 마감 예정 시각 설정 및 자동 마감

### P2 (이번 연습에서 제외)
- 메뉴 관리(등록·수정), 정산(송금) 추적, 알림

## 6. API 계약 (초안)

| Method | Path | 설명 | 응답 |
|---|---|---|---|
| POST | /api/auth/fake-login | `{ userId }` → 세션 쿠키 발급 | 200 |
| GET | /api/auth/me | 현재 사용자 | 200 / 401 |
| GET | /api/menus | 메뉴 목록 | 200 |
| GET | /api/rounds | 모집 목록 | 200 / 401 |
| POST | /api/rounds | 모집 개설 `{ date, title }` | 201 / 400 / 401 |
| GET | /api/rounds/:id | 모집 상세 (상태, 주문 현황, 취합표) | 200 / 401 / 404 |
| POST | /api/rounds/:id/close | 마감 (개설자만) | 204 / 401 / 403 / 404 / 409 |
| POST | /api/rounds/:id/orders | 주문 `{ menuId, quantity, memo? }` | 201 / 400 / 401 / 404 / 409 |
| DELETE | /api/orders/:id | 주문 취소 (본인만, 모집 중일 때만) | 204 / 401 / 403 / 404 / 409 |
| POST | /api/test/reset | **테스트 환경 전용** 모집·주문 초기화 | 204 |

**오류 코드**

| 상황 | 상태 | code | message |
|---|---|---|---|
| 입력값 오류 | 400 | `VALIDATION_ERROR` | (검증 메시지) |
| 비로그인 | 401 | `UNAUTHORIZED` | 로그인이 필요합니다 |
| 권한 없음 | 403 | `FORBIDDEN` | (상황별) |
| 1인 1주문 위반 | 409 | `ORDER_DUPLICATE` | 이미 주문했습니다 |
| 마감된 모집 | 409 | `ROUND_CLOSED` | 주문이 마감되었습니다 |

요청/응답 스키마는 `packages/contracts`에 Zod로 정의하고 FE/BE가 공유한다.

## 7. 비기능 요구사항
- 오류 응답 형식: `{ "error": { "code": "ROUND_CLOSED", "message": "주문이 마감되었습니다" } }`
- **1인 1주문은 DB 제약으로 보장**한다. 같은 사용자가 동시에 두 번 주문해도 하나만 생성된다.
- **금액은 서버 계산**: 클라이언트가 가격·금액을 보내도 사용하지 않는다.
- 금액 표시는 천 단위 콤마 + "원" (예: `27,000원`).
- `/api/test/reset`은 `NODE_ENV=test`일 때만 라우트를 등록한다.
- 날짜는 `YYYY-MM-DD`(Asia/Seoul 기준 날짜)로 다룬다.
