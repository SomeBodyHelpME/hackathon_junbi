# PRD — 팀 일정 투표 (모의 개발용)

## 1. 목적
팀 회의·회식 일정을 정할 때, 개설자가 후보 시간을 올리고 팀원이 가능한 시간을 고르면 가장 많이 가능한 시간을 보여 주고, 개설자가 하나로 확정하는 웹 서비스.
해커톤 전 **BDD → AI 구현 → E2E 검증** 사이클을 연습하기 위한 축소 범위 프로젝트 (kit-03).

## 4. 용어
- **투표(Poll)**: 제목, 개설자, 후보 시간 2~5개, 상태(`투표 중` / `확정`), 확정된 후보.
- **후보(Candidate)**: 투표에 속한 시작 일시 하나. 30분 단위, Asia/Seoul 기준으로 입력·표시.
- **응답(Response)**: 한 사용자가 한 투표에서 "가능"으로 고른 후보들의 집합. **투표당 1인 1응답이며, 다시 제출하면 이전 응답을 대체한다.**
- **집계**: 후보별 가능 인원 수. 가능 인원이 가장 많은 후보(동률이면 모두)를 **최다 득표 후보**로 표시한다.

## 5. 요구사항

### REQ-01 투표 생성 (P0)
- 로그인한 사용자는 제목과 후보 시간(날짜 + 시각) 2~5개를 입력해 투표를 만든다.
- 같은 투표 안에서 후보 시간은 중복될 수 없다.

**인수조건**
- AC-01: 제목과 후보 시간을 입력해 투표를 만들면 "투표" 목록에 표시된다.
- AC-02: 후보가 2개 미만이면 "후보는 2개 이상 5개 이하로 입력하세요" 오류가 표시되고 투표는 생성되지 않는다.
- AC-03: 후보 시간이 중복되면 "같은 후보 시간이 중복되었습니다" 오류가 표시되고 투표는 생성되지 않는다.

### REQ-02 응답 및 집계 (P0)
- 투표 중인 투표에서 가능한 후보를 하나 이상 골라 응답한다.
- 다시 응답하면 이전 응답을 **대체**한다 (인원이 이중으로 세지지 않는다).
- 후보별 가능 인원과 최다 득표 후보를 보여 준다.

**인수조건**
- AC-04: 가능한 후보를 골라 응답하면 집계에 후보별 가능 인원이 반영되고, 새로고침 후에도 유지된다.
- AC-05: 다시 응답하면 이전 응답이 새 응답으로 바뀐다.
- AC-06: 가능 인원이 가장 많은 후보가 최다 득표 후보로 표시된다. 동률이면 모두 표시된다.
- AC-07: 아무 후보도 고르지 않고 응답하면 "가능한 시간을 하나 이상 선택하세요" 오류가 표시되고 집계는 바뀌지 않는다.

### REQ-03 일정 확정 (P0, 보안)
- 개설자는 후보 하나를 골라 투표를 확정한다. 확정된 투표에는 응답할 수 없다.
- 개설자가 아닌 사용자는 확정할 수 없다 (버튼 미노출 + API 403).
- 확정 요청의 후보는 **그 투표의 후보**여야 한다. 다른 투표의 후보 id로 요청하면 400.
- 로그인하지 않은 요청은 401.

**인수조건**
- AC-08: 개설자가 후보 하나로 확정하면 상태가 "확정"으로, 확정된 시간이 표시되고 응답 양식이 사라진다.
- AC-09: 개설자가 아닌 사용자에게는 확정 버튼이 없고, API로 확정을 요청하면 **403**, 상태는 유지된다.
- AC-10: 확정된 투표에 API로 응답하면 **409** `POLL_CONFIRMED`로 거부된다.
- AC-11: 다른 투표의 후보로 확정을 요청하면 **400** `INVALID_CANDIDATE`로 거부되고 상태는 유지된다.
- AC-12: 비로그인 상태의 응답 API 요청은 **401**.

### P1 (시간이 남으면)
- 응답 마감 시각, 후보 추가·삭제, 확정 취소
### P2 (제외)
- 캘린더 연동, 알림, 익명 투표

## 6. API 계약 (초안)

| Method | Path | 설명 | 응답 |
|---|---|---|---|
| POST | /api/auth/fake-login | `{ userId }` → 세션 쿠키 | 200 |
| GET | /api/auth/me | 현재 사용자 | 200 / 401 |
| GET | /api/users | 팀원 목록 | 200 |
| GET | /api/polls | 투표 목록 | 200 / 401 |
| POST | /api/polls | 생성 `{ title, candidates: [{ startsAt }] }` (ISO 8601, +09:00) | 201 / 400 / 401 |
| GET | /api/polls/:id | 상세 (후보별 가능 인원, 최다 득표, 내 응답, 확정 후보) | 200 / 401 / 404 |
| PUT | /api/polls/:id/response | 내 응답 저장/대체 `{ candidateIds: [] }` | 200 / 400 / 401 / 404 / 409 |
| POST | /api/polls/:id/confirm | 확정 `{ candidateId }` (개설자만) | 204 / 400 / 401 / 403 / 404 / 409 |
| POST | /api/test/reset | **테스트 전용** 투표·응답 초기화 | 204 |

**오류 코드**

| 상황 | 상태 | code | message |
|---|---|---|---|
| 입력값 오류 | 400 | `VALIDATION_ERROR` | (검증 메시지) |
| 이 투표의 후보가 아님 | 400 | `INVALID_CANDIDATE` | 이 투표의 후보가 아닙니다 |
| 비로그인 | 401 | `UNAUTHORIZED` | 로그인이 필요합니다 |
| 개설자 아님 | 403 | `FORBIDDEN` | 투표를 만든 사람만 확정할 수 있습니다 |
| 확정된 투표 | 409 | `POLL_CONFIRMED` | 이미 확정된 투표입니다 |

## 7. 비기능 요구사항
- 오류 응답 형식: `{ "error": { "code": "...", "message": "..." } }`
- **1인 1응답은 DB 제약으로 보장**하고, 다시 제출은 대체(upsert)한다. 같은 사용자의 동시 제출에도 응답은 하나만 남는다.
- 응답·확정이 동시에 들어와도 확정 이후 응답이 저장되지 않는다.
- 응답의 후보 id도 그 투표의 후보인지 서버가 검증한다.
- 시각은 `timestamptz`로 저장, 화면은 Asia/Seoul `YYYY-MM-DD HH:MM`으로 표시.
- `/api/test/reset`은 `NODE_ENV=test`일 때만 등록한다.
