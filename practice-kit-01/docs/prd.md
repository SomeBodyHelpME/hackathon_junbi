## 4. 요구사항

### REQ-01 예약 생성 및 조회 (P0)
- 로그인한 사용자는 회의실, 날짜, 시작 시각, 종료 시각, 제목을 입력해 예약할 수 있다.
- 예약은 DB에 저장되며, 새로고침 후에도 "내 예약" 목록에 표시된다.
- 시각은 30분 단위로 선택한다.

**인수조건**
- AC-01: 정상 입력 시 예약이 생성되고 "내 예약" 목록에 표시된다.
- AC-02: 새로고침 후에도 예약이 유지된다.
- AC-03: 제목이 비어 있으면 "제목을 입력하세요" 오류가 표시되고 예약은 생성되지 않는다.
- AC-04: 종료 시각이 시작 시각보다 빠르거나 같으면 "종료 시각은 시작 시각 이후여야 합니다" 오류가 표시된다.

### REQ-02 중복 예약 차단 (P0)
- 같은 회의실에 시간이 겹치는 예약은 생성할 수 없다.
- 경계가 맞닿는 경우(10:00~11:00 뒤에 11:00~12:00)는 허용한다.
- 중복 검사는 **반드시 백엔드에서** 수행한다 (프론트 검사만으로는 불충분).

**인수조건**
- AC-05: 겹치는 시간에 예약하면 "이미 예약된 시간입니다" 오류가 표시되고 예약은 생성되지 않는다.
- AC-06: 경계가 맞닿는 예약은 정상 생성된다.
- AC-07: 다른 회의실이면 같은 시간이어도 예약할 수 있다.

### REQ-03 예약 취소 (P0, 보안)
- 사용자는 본인의 예약만 취소할 수 있다.
- 다른 사용자의 예약에는 취소 버튼이 보이지 않는다.
- API로 다른 사용자의 예약 취소를 직접 요청하면 **403**을 반환하고 예약은 유지된다.
- 로그인하지 않은 요청은 **401**을 반환한다.

**인수조건**
- AC-08: 본인 예약을 취소하면 목록에서 사라지고 새로고침 후에도 없다.
- AC-09: 타인 예약에는 취소 버튼이 없다.
- AC-10: 타인 예약 취소 API 요청은 403, 예약은 유지된다.
- AC-11: 비로그인 상태의 예약 생성/취소 API 요청은 401.

## 5. API 계약 (초안)

| Method | Path | 설명 | 응답 |
|---|---|---|---|
| POST | /api/auth/fake-login | `{ userId }` → 세션 쿠키 발급 | 200 |
| GET | /api/rooms | 회의실 목록 | 200 |
| GET | /api/reservations?mine=true | 내 예약 목록 | 200 |
| GET | /api/reservations?roomId=&date= | 회의실·날짜별 예약 | 200 |
| POST | /api/reservations | 예약 생성 | 201 / 400 / 401 / 409 |
| DELETE | /api/reservations/:id | 예약 취소 | 204 / 401 / 403 / 404 |
| POST | /api/test/reset | **테스트 환경 전용** 예약 데이터 초기화 | 204 |

요청/응답 스키마는 `packages/contracts`에 Zod로 정의하고 FE/BE가 공유한다.

## 6. 비기능 요구사항
- 시각은 서버에서 `timestamptz`로 저장하고, 화면은 Asia/Seoul 기준으로 표시한다.
- `/api/test/reset`은 `NODE_ENV=test`일 때만 라우트를 등록한다.
- 오류 응답 형식: `{ "error": { "code": "RESERVATION_CONFLICT", "message": "이미 예약된 시간입니다" } }`
